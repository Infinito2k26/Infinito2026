# API Reference

> Generated by `/create-rules`. Update this when endpoints or contracts change.

## Global Standards

- **Base path**: `/api/v1` (or `/`)
- **Authentication**: <!-- Bearer JWT | API key | Session cookie | None -->
- **Content type**: `application/json`
- **Response envelope**:

```json
{
  "success": true,
  "data": { ... },
  "error": null,
  "meta": { "page": 1, "total": 42 }
}
```

Error shape:
```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Human-readable message",
    "fields": { "email": "Invalid format" }
  }
}
```

## Status Codes

| Code | When to use |
| ---- | ----------- |
| 200 | Successful GET, PUT, PATCH |
| 201 | Successful POST that created a resource |
| 204 | Successful DELETE (no body) |
| 400 | Validation error or malformed request |
| 401 | Not authenticated |
| 403 | Authenticated but not authorized |
| 404 | Resource not found |
| 409 | Conflict (duplicate, state mismatch) |
| 422 | Semantically invalid (business rule violation) |
| 429 | Rate limit exceeded |
| 500 | Server error (never expose stack traces) |

## Contract Rules

- Never break an existing field shape without a version bump.
- Additive changes (new optional fields) are non-breaking.
- Never expose internal IDs, stack traces, or raw database errors.
- Pagination uses `page` + `limit` query params. Max `limit` is 100.
- Timestamps are ISO 8601 UTC strings: `"2024-01-15T10:30:00Z"`.
- Money is in the smallest currency unit (e.g., cents for USD).
