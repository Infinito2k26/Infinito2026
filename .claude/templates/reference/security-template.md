## Authorization Matrix

| Role | Resource | Can | Cannot |
| ---- | -------- | --- | ------ |
| Admin | All | CRUD | — |
| User | Own resources | Read, update | Delete others' |
| Guest | Public resources | Read | Create, modify |

## Sensitive Data Inventory

| Data | Classification | Where stored | Protection |
| ---- | -------------- | ------------ | ---------- |
| Passwords | Critical | DB (hashed) | bcrypt |
| Payment info | Critical | Payment processor only | Never stored locally |
| PII (email, name) | Sensitive | DB | Encrypted at rest |
| Session tokens | Sensitive | DB / Redis | Short TTL |
| API keys | Critical | Env vars | Never in code |

## Input Validation Rules

- Validate all user input at the API boundary — never trust client-side validation alone.
- Use an allow-list (permitted values) not a block-list (banned values) for string validation.
- Sanitize HTML output if any user content is rendered as HTML.
- Parameterized queries only — never string-concatenate SQL.
- File uploads: validate MIME type + extension, limit size, store outside web root.

## Common Risks and Mitigations

| Risk | OWASP | Mitigation |
| ---- | ----- | ---------- |
| SQL injection | A03 | Parameterized queries / ORM |
| XSS | A03 | Output encoding, CSP headers |
| Broken access control | A01 | Authorization checks on every route |
| Sensitive data exposure | A02 | Encryption at rest + in transit (HTTPS) |
| Security misconfiguration | A05 | Least-privilege, secrets rotation |
| CSRF | A01 | SameSite cookies, CSRF tokens |
| Rate limiting abuse | A04 | Per-IP and per-user rate limits |
| Insecure dependencies | A06 | Automated dependency scanning |

## Security Headers

All API responses must include:

```text
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Content-Security-Policy: <policy>
Referrer-Policy: no-referrer
```

## Secrets Management Rules

- All secrets in environment variables — never in source code or git history.
- Rotate secrets immediately if accidentally committed.
- Different secrets per environment (dev, staging, prod).
- Least privilege: each service only gets the secrets it needs.
