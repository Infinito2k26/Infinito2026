## What Must Always Have Tests

- All API endpoints (status code + response shape).
- All business logic with branching conditions.
- All auth and authorization paths.
- All database constraint behaviors (duplicates, FK violations).
- All background job side effects.

## What Does NOT Need Tests

- Simple wrappers with no branching logic.
- Configuration files.
- Third-party library behavior.
- UI pixel accuracy (use screenshots instead).

## PR Verification Notes

For every PR, include in the PR body:

- Commands run and their pass/fail status.
- Commands not run and why (e.g., "E2E skipped — no services available in CI").
- Screenshots or request IDs for any UI or API change.
- Known gaps to address in follow-up issues.
